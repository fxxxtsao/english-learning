# 後續優化與待驗證清單

最後更新：2026-09-09（連續運作 7 天後）

系統目前每個環節都已實測通過：抓文章、上傳素材、Spark 出題、音檔下載進 Drive、音檔取回播放、網頁練習、每日健檢。這份清單記的是「還沒被時間驗證的」與「知道可以更好但當下不急的」部分。

---

## 值得優化

### clasp：Apps Script 的部署自動化

**問題**：目前改一次 Apps Script 要手動貼三個檔案再重新部署，而且「重新部署」有兩條路——「管理部署作業 → 編輯 → 版本改新版本」會沿用同一個網址，「新增部署作業」則會產生新網址。首次部署當天連續踩了三次：貼了忘記部署、部署時選錯選項產生新網址、裝置還連著舊網址。

這三次的共同點是**失敗訊息完全指不到真正的原因**——你看到的是「不明錯誤」「unknown_action」「19 列資料損壞」，沒有一個提到部署。

**做法**：裝 Google 官方的 `clasp` 命令列工具，改完在電腦上一行指令推送，自動建立新版本，網址不變。約十分鐘設定。

**為什麼還沒做**：當下正在讓管線跑通，同時處理兩件事會讓問題來源難以分辨。現在跑通了，這是最值得先做的一項。

### 音檔傳輸是全系統最慢的一段

**問題**：Apps Script 無法回傳二進位內容，音檔只能編碼成文字（base64）夾在 JSON 裡傳，資料量膨脹三分之一；加上 spec 決定音檔存原檔不裁切，傳的是整篇文章的朗讀（實測 3–6 MB）。第一次載入某課會明顯等待。

**可能做法**：下載時就只留練習需要的那段（目前是前 180 秒）。這會改動 spec 裡「音檔不裁切」那個決策，而那個決策當初是為了省掉整個音訊處理環節——所以這不只是效能取捨，要一併衡量複雜度。

**先觀察**：Service Worker 會預先把最近七天的音檔快取起來，所以「等待」理論上只發生在第一次。實際用過幾週再判斷值不值得動。

### BBC 這條備援路其實是死的

**問題**：提示詞裡還寫著「VOA 素材用完時改用 BBC」，但實測 BBC 設有 Google-Extended Opt-Out，明確排除 Google 的 AI 抓取——Spark 永遠到不了。這條備援在需要它的那天會直接失效。

**做法**：素材抓取本來就已經改由本機腳本負責，所以真正該做的是讓 `tools/fetch-materials.js` 支援 BBC，而不是叫 Spark 去抓。等 VOA 存量真的見底再處理即可（約兩年份）。

## 待驗證（需要時間或使用量累積）

這些不是問題，是還沒有足夠資料判斷。

~~**每日排程是否真的會自動跑**~~：**2026-09-09 已驗證**。連續 7 天每天都有新課，音檔回填率 7/7，兩個排程都確實自動執行。

~~**音檔抓取的時間點對不對**~~：**2026-09-09 已驗證**。音檔回填率 100% 代表抓取時間排在 Spark 之後，設定是對的。

**難度自適應**：要累積 20 題作答才會第一次調整，之後看它有沒有真的往上爬。這條路徑最容易斷在「網頁算出新等級卻沒寫回試算表」，spec 特別點名過。

**複習排程**：答錯的題目與不熟的單字要幾天後才會再出現，短期內看不出對錯。

**離線功能**：Service Worker 的七天音檔預抓、PWA 加到主畫面，都還沒在真實的通勤情境下測過。

**spec 的「連續供應率」還缺基準線**：其餘驗收查詢已於 2026-09-09 回填實測值，只有這一項要求跑滿 30 天才有意義，目前累積 7 天。滿一個月後把數字寫回 `docs/specs/2026-09-02-content-pipeline.md`。

## 已知限制（判斷後決定不修）

**同步權杖走網址列**：Apps Script 的 `doGet` 讀不到自訂的請求標頭，這是平台限制，要改就得把所有讀取都變成寫入式請求。修掉音檔的歸屬檢查之後，權杖外洩的最大損失只剩「答題紀錄被看到或被亂寫」，spec 已明確接受這個範圍。

**上傳答題紀錄時每次掃全表去重**：一年約兩萬筆，要好幾年後才會慢到有感。現在改屬於提前優化。

**測試資料跑健檢一定會出現錯誤**：`test/fixtures/lessons-rows.json` 裡的壞資料共用同一個 `source_url`，所以拿它跑健檢必然報重複。那是刻意設計的樣本，不是工具的問題。

## 補貨怎麼做

存量低於十位數時跑這兩行，重複的文章會被自動擋掉，隨時可以跑：

```
node tools/fetch-materials.js --count 100 --pages 8
node tools/upload-materials.js materials.json
```

健檢報告最後一行「素材庫存」就是還剩幾天份。
