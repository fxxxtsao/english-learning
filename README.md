# English Learning 系統部署與維護手冊

## 系統簡介
這是一個專為通勤與零碎時間設計的個人英文學習系統。教材文章與音檔會先一次抓好幾十上百篇存進試算表當存量，之後每天自動從存量中挑一篇產生閱讀與聽力測驗。使用者可以在任何裝置的網頁瀏覽器上練習，支援離線操作與跨裝置進度同步。

## 每日運作流程
系統分成兩種節奏。

**偶爾一次的補貨**：在自己電腦上執行 `tools/fetch-materials.js`，它會去 VOA Learning English 抓數十篇文章的全文與音檔網址，再用 `tools/upload-materials.js` 寫進試算表，成為「素材列」——內容備妥、題目還沒出。一次抓一百篇大約可以用三個月。

**每天自動跑的部分**：早上 Gemini Spark 從素材中挑一篇還沒出題的，產生閱讀題、聽力題與單字，寫回同一列，那一列就成為當天的課。一小時後 Google Apps Script 自動啟動，把該篇的音檔下載到你的 Google 雲端硬碟並回填檔案代號。你在通勤或空檔打開網頁，就會看到當天的教材；網頁會依你近期的答對率自動調整難度，並寫回試算表供 Spark 隔天選材參考。

為什麼抓取要在自己電腦上做，而不是交給 Spark 一手包辦：實測發現來源網站會拒絕 Google 的 AI 抓取（VOA 直接回絕、BBC 明文排除），同一個網址從自己電腦取用則完全正常。Spark 因此只保留它做得到的部分——讀試算表、出題、寫短欄位。詳細經過記在 `docs/specs/2026-09-02-content-pipeline.md`。

## 首次設定步驟
設定分為七個階段，必須依序進行。

建立 Google 試算表
首先，請在 Google 雲端硬碟建立一份全新的空白試算表，並命名為「English Learning」。完成後，你可以在試算表的左上角看到剛輸入的名稱，這代表試算表已經準備好作為系統的資料庫。

部署 Apps Script
接著，在該試算表的選單中點選「擴充功能」並選擇「Apps Script」，這會開啟一個程式碼編輯器。在這個編輯器中，請參考 `apps-script/README.md` 的「檔案職責說明」與「貼上的順序」，依序建立並貼上三個檔案的程式碼。貼齊後，請照著同一份文件裡「部署為網頁應用程式」一節的步驟，把這個專案部署成網頁應用程式（需要指定執行身分與存取權限，不是存完檔就自動完成）。部署完成後，你會取得一個以 `https://script.google.com/.../exec` 結尾的網址，這表示應用程式伺服器已經成功啟動並準備好接收網頁的請求。

執行 setupSheets 與 generateToken
在 Apps Script 編輯器中，請先選擇 `setupSheets` 函式並點擊執行，這會在你的試算表中自動建立所需的格式。你可以回到試算表，確認下方是否出現了 `lessons`、`progress` 與 `settings` 三個分頁，這代表格式建立成功。接著，選擇 `generateToken` 函式並執行，查看下方的執行記錄檔，裡面會印出一串長英數字密碼，這代表系統已經產生了專屬的同步權杖，請將這串權杖複製保存。

還有一件事一定要做：**回試算表把預設的「工作表1」分頁刪掉。** 新建試算表時 Google 會自動給你一個空白分頁，`setupSheets` 不會去動它（刪分頁不可逆，不適合由程式自動決定）。但這個多出來的空分頁實測會讓 Gemini Spark 寫錯地方——它會把每日教材寫進那個空分頁，你在 `lessons` 分頁完全看不到，而且不會有任何錯誤訊息。執行 `setupSheets` 後的執行記錄檔會列出所有多餘分頁，照著刪即可。

安裝觸發器
同樣在 Apps Script 編輯器中，選擇 `installTriggers` 函式並執行。執行完畢後，請點擊左側的「觸發條件」圖示（時鐘圖案），如果你看到清單中出現了 `fetchPendingAudio` 與 `cleanupOldAudio` 兩個排程，就代表系統已經知道要在固定的時間去抓取音檔與清理舊檔案。

在 Gemini Spark 建立每日排程任務並貼上提示詞
請前往 Gemini Spark 建立一個每日排程任務。開啟本專案中的 `docs/prompts/spark-daily-lesson.md` 檔案，將裡面的提示詞本文完整複製，貼到排程任務的設定中，並設定每天早上執行。隔天早上你可以打開試算表的 `lessons` 分頁，如果看到新增了一列包含文章與題目的資料，就代表機器人已經成功開始為你準備每日教材。

請記住你在這裡實際設定的執行時間。上一步安裝的音檔下載排程，預設是假設 Spark 在早上七點執行，才抓晚一小時的音檔；如果你這裡設定的時間不是早上七點左右，回頭到 `apps-script/README.md` 的「觸發器的時間設定」一節，調整 `AudioFetcher.gs` 裡的時間設定，否則音檔下載任務可能會在 Spark 還沒把當天文章寫進試算表之前就先執行，抓不到當天的內容。

抓取教材素材並上傳
在自己的電腦上，於專案資料夾執行下面兩行。第一行會去來源網站抓二十篇文章的全文與音檔網址，存成本機檔案；第二行把它們寫進試算表。兩行都只新增資料，不會刪改任何既有內容，重複的文章會被伺服器自動擋掉，所以跑幾次都安全。
`node tools/fetch-materials.js --count 20 --pages 3`
`node tools/upload-materials.js materials.json`
第二行需要讀取你的 Apps Script 網址與同步權杖，預設會從專案根目錄的 `MY-SETUP.local.md` 讀（那個檔案不會進版控）；你也可以用 `--url` 與 `--token` 直接指定。上傳完成後回試算表看，`lessons` 分頁應該多出二十列有標題與內文、但 A 欄空白的資料，那就是還沒出題的素材。

開啟 GitHub Pages
請將這個專案的程式碼推送到你自己的 GitHub 儲存庫，並在設定中開啟 GitHub Pages 網頁代管功能。等待幾分鐘後，訪問 GitHub Pages 提供的網址，如果你能看到系統的初始設定畫面，這代表網頁應用程式已經成功上線。

在手機與電腦首次開啟網頁輸入網址與同步權杖
最後，請分別在手機與電腦的瀏覽器中打開剛剛的 GitHub Pages 網址。請將先前取得的 Apps Script 網址與同步權杖貼上並儲存。送出後，如果網頁順利切換到載入中或顯示今日練習的畫面，且沒有跳出錯誤訊息，就代表這台裝置已經成功與你的專案資料庫連線，設定大功告成。

這組網址與權杖只會存在你當下操作的這個瀏覽器裡（不會寫進程式碼、也不會上傳到 GitHub），所以手機和電腦必須各自輸入、儲存一次，缺一台就代表那一台還沒設定。之後如果清除瀏覽器資料、換瀏覽器或換裝置，也要重新輸入一次。

## 日常維護
日常的維護工作包含以下幾個部分。

每日健檢怎麼跑
系統提供了一支健檢程式，用來驗證資料是否完整。第一次使用前，你可以先拿專案內附的範例資料試跑一次，熟悉報告長什麼樣子，這個步驟不需要你的 Apps Script 已經部署好：
`node tools/healthcheck.js test/fixtures/lessons-rows.json`
這份範例資料是刻意寫壞的測試樣本，用來示範報告的各種項目長什麼樣子，所以執行後你會看到多項「FAIL」以及一筆 source_url 重複的警告，這是設計好的結果，不代表健檢工具本身有問題。

確認報告格式沒問題後，正式檢查你自己的資料時，請開啟命令列工具，輸入以下指令（把 `<exec網址>` 換成你部署時取得、以 `/exec` 結尾的網址，`<同步權杖>` 換成 `generateToken` 印出來的那串字）：
`node tools/healthcheck.js "<exec網址>?token=<同步權杖>"`
網址後面務必自己加上 `?token=` 加上你的同步權杖，這個工具不會幫你自動帶入權杖；如果漏掉，伺服器會判定為未授權而回報失敗，並不是工具壞掉或資料有問題。這個指令會向伺服器請求資料並進行驗證，執行完畢後螢幕上會印出一份報告，告訴你是否有遺漏的欄位或格式錯誤，這並不會修改任何現有資料。

改了 js/lesson.js 或 js/contract.js 之後的處理
如果你修改了 `js/lesson.js` 或 `js/contract.js` 這兩個檔案，你必須更新 Apps Script 端的程式碼。請在命令列中輸入以下指令來重新打包共用程式：
`node tools/build-shared.js`
這會讀取你修改過的檔案並自動產生一個新的 `apps-script/Shared.gs` 檔案。執行完成後，請務必將這個新檔案的內容，完整複製並覆蓋到 Apps Script 編輯器中的 `Shared.gs` 裡。光是貼上並存檔還不夠——因為網頁連線的是部署後的固定網址，存檔並不會自動讓那個網址套用新程式碼，你還必須照 `apps-script/README.md`「部署為網頁應用程式」一節，重新部署一次新版本，網頁與伺服器才會真正使用相同的邏輯。

教材存量的補貨
健檢報告最後一行的「素材庫存」就是還剩幾天份的教材。數字低於十位數時，執行下面兩行補貨，參數可以調大：
`node tools/fetch-materials.js --count 100 --pages 8`
`node tools/upload-materials.js materials.json`
抓過的文章會因為網址重複而被自動跳過，所以不必擔心抓到重複的內容，也不必記得上次抓到哪裡。

怎麼跑測試
若要確保系統邏輯正確，你可以執行自動化測試。請在命令列中輸入以下指令：
`node --test`
這會自動找到測試資料夾中的所有檢查項目並執行（不需要自己指定 `test/` 路徑，指定路徑在某些 Node.js 版本上反而會找不到測試檔而直接失敗）。執行結束後，系統會告訴你通過了多少測試以及是否有錯誤發生，這同樣不會對你的實際學習資料造成任何影響。

## 後續優化與待驗證

還沒做完的事、還沒被時間驗證的事，都記在 `docs/backlog.md`。第一項是裝 clasp 來自動化 Apps Script 的部署——首次部署當天有三次卡關都出在手動部署的步驟，而且錯誤訊息都指不到真正的原因。

## 已知限制
本系統仰賴 Gemini Spark 的自然語言生成能力，產出的文字格式偶爾可能不符合標準，導致當日內容無法解析——每日健檢就是為了及早發現這件事。其次，來源網站的改版可能會讓 `tools/fetch-materials.js` 抓不到內容，此時需要調整該檔案裡解析網頁的部分；不過因為教材是一次抓一大批存著，這種失效不會立刻中斷每天的供應，你有充裕的時間處理。另外要注意 VOA Learning English 自 2025 年 3 月起已停止產出新內容，目前用的是它的存量（約兩年份），用完後需要改用其他來源。此外，由於 Google Apps Script 執行時間限制為六分鐘，如果來源音檔過大或網路連線過慢，可能會導致音檔下載中斷。最後，系統設計為個人使用，並無多使用者隔離與帳號登入機制。
